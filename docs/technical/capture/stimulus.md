# Controlled stimulus

PHROMs only exercise the parameter combinations that someone happened to encode. An emulator needs every path covered. The bench has two mechanisms for controlled input: Speak External, and synthetic VSM images served by the Pico. The vectors are generated by `investigation/tools/vectors.py`; what they found is in [synthetic vectors](work/synthetic-vectors.md).

## Speak External (command `0x6x`)

The Pico writes LPC frames straight into the 16-byte FIFO. This gives complete control over the bit stream with no VSM involved. It carries **synthetic test vectors** generated by a host script:

- **Single-parameter sweeps.** Every parameter is held at a neutral value and one index is stepped through its whole range: every energy index (0–15), every pitch index (0–63), and every K1–K10 index. These tests read out the chip's internal parameter lookup tables one entry at a time.
- **Voiced and unvoiced.** The same parameters with pitch = 0 (noise) against pitch ≠ 0 (the chirp excitation). Long unvoiced runs characterise the noise generator (its LFSR sequence and period).
- **Interpolation.** Pairs of frames with large parameter jumps, to capture the per-interpolation-period stepping, and the documented rule that interpolation is inhibited across voiced/unvoiced and silence transitions.
- **Special frames.** Repeat frames, energy = 0 (silence), and the stop code (energy = 15), including the "interpolate to zero" tail.
- **FIFO and protocol behaviour.** Start-up with exactly 8, then 9, bytes (TS should go high at 9). The FIFO starved deliberately mid-utterance (BE, abnormal termination, `INT`). The BL threshold timing. Whether Reset is ignored during Speak External.
- **Pathological input.** Random bit streams, for robustness and determinism.

## Synthetic VSM images

The Pico serves arbitrary VSM data. The same vectors are packed into a synthetic PHROM to test the VSM path: Read-and-Branch, Load-Address nibble sequencing, Read Byte (`0x1x`), and address wrap-around at bank boundaries. Comparing the Speak External and VSM versions of the same vector shows whether the two input paths are equivalent.

## Timing and handshake tests

The VSM trace and the trigger GPIO also give timestamps for: READY assertion times, the delay from Speak to first fetch, how the fetches line up with frame boundaries, how many bits per frame the chip reads ahead, and the reset/power-up sequence. This is the information an emulator needs to be *cycle*-accurate on the host interface, not just sample-accurate on audio. `investigation/tools/protocol.py` runs these tests from the Pico's trace, with no scope ([synthetic vectors](work/synthetic-vectors.md)).

## Confirmation with new speech data

These tests confirm that the documented mechanism is correct and complete, using speech data the chip has never seen. Everything is produced from the datasheet and the project's own tools, with no reference to the original PROMs or to other emulators. The results are in [new speech data](work/new-speech-data.md).

1. **Generate the data.**
    - Phrases encoded by the project's [encoder](../encoder/index.md) from new recordings, for example a set of words and sentences not present in any original PROM.
    - Hand-designed frame sequences that use every feature: voiced, unvoiced, repeat and silence frames, the stop code, large interpolation jumps, and extreme parameter values.
2. **Package it two ways:**
    - as a new VSM/PHROM image with its own word table, laid out as the [authoring guide](../datasheet/authoring.md) describes, and
    - as Speak External byte streams.
3. **Predict.** Run the [reference emulator](../emulator/index.md) on each item. Commit the predicted samples and the predicted VSM fetch sequence *before* the chip is run, so the prediction cannot be adjusted to fit the result.
4. **Run on the chip.** Play every item through the Pico (VSM emulation and Speak External), using the standard procedure ([automation](automation.md#the-standard-procedure)), and capture it like any other PROM.
5. **Compare.** The captured `I/O` samples must match the prediction within the tolerance ([acceptance tests](index.md#the-tolerance)). The VSM trace must match the predicted fetches. The VSM and Speak External versions of each item must produce the same output.
6. **Listen.** Each phrase must be intelligible and must sound as intended. This catches a datasheet and an emulator that agree with each other but are both wrong in the same way.

Any mismatch is a gap in the datasheet. The documentation is fixed first, then the data is regenerated and the whole set rerun. The new speech data, its predictions and its captures are published as part of the data set, as a worked example of authoring.

If the authored image is meant for a physical PHROM replacement, a BBC Micro's speech system should also be checked to read its word table and speak the words. That check has not been made ([known gaps](../datasheet/gaps.md#the-acorn-phrom-format-and-the-bbc-micro)).
